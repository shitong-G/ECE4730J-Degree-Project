# SOTA Baseline Comparison Plan

This project can compare RT-DETR against YOLOv8n, PP-PicoDet, and
NanoDet-Plus on the same video locally and on Raspberry Pi. Treat these as
lightweight open-source detector baselines rather than the newest detector SOTA:
they are useful because they are public, small, edge-oriented, and deployable.

## Model Availability

| Model | Open weights | ONNX path | Pi-friendly path | Recommendation |
| --- | --- | --- | --- | --- |
| YOLOv8n | Official `yolov8n.pt` via Ultralytics | Direct `yolo export format=onnx` | ONNX Runtime CPU, or Ultralytics NCNN export | Use as the cleanest ONNX baseline. |
| PP-PicoDet-S 320 | Official PaddleDetection `.pdparams` | Export Paddle inference, then `paddle2onnx` | Paddle Lite first, ONNX Runtime as fallback | Use native Paddle/Paddle Lite results if ONNX conversion is fragile. |
| NanoDet-Plus-m 320 | Official NanoDet checkpoint | Official `tools/export_onnx.py` | NCNN first, ONNX Runtime as fallback | Use ONNX locally and NCNN/ONNX on Pi depending on install friction. |

Keep the exact input size in every result table. YOLOv8n is normally reported at
640, while PicoDet-S and NanoDet-Plus-m are common 320-resolution edge
variants. If the thesis needs a strict same-resolution comparison, also export
YOLOv8n at 320 and run RT-DETR 320.

## Directory Contract

```text
models/baselines/
  yolov8n.pt
  yolov8n_640.onnx
  picodet_s_320_coco_lcnet_portable/

```

The shared manifest is [configs/sota_baselines.yaml](../configs/sota_baselines.yaml).

## Local Preparation

YOLOv8n is the fastest to prepare:

```bash
python -m pip install ultralytics onnx onnxslim
yolo export model=yolov8n.pt format=onnx imgsz=640 opset=12 simplify=True
mkdir -p models/baselines
mv yolov8n.onnx models/baselines/yolov8n_640.onnx
```

PicoDet uses PaddleDetection as the source of truth:

```bash
git clone --depth 1 --branch release/2.7 https://github.com/PaddlePaddle/PaddleDetection.git third_party/PaddleDetection
python -m pip install paddlepaddle paddle2onnx
python third_party/PaddleDetection/tools/export_model.py \
  -c third_party/PaddleDetection/configs/picodet/picodet_s_320_coco_lcnet.yml \
  --output_dir models/baselines \
  -o weights=https://paddledet.bj.bcebos.com/models/picodet_s_320_coco_lcnet.pdparams
paddle2onnx \
  --model_dir models/baselines/picodet_s_320_coco_lcnet \
  --model_filename model.pdmodel \
  --params_filename model.pdiparams \
  --save_file models/baselines/picodet_s_320.onnx \
  --opset_version 12
```

NanoDet-Plus uses its official exporter:

```bash
git clone --depth 1 https://github.com/RangiLyu/nanodet.git third_party/nanodet
python -m pip install gdown
python scripts/prepare_sota_baseline_artifacts.py --models nanodet_plus_m_320
python -m pip install torch onnx onnxruntime
python third_party/nanodet/tools/export_onnx.py \
  --cfg_path third_party/nanodet/config/nanodet-plus-m_320.yml \
  --model_path models/baselines/nanodet-plus-m_320.ckpt \
  --out_path models/baselines/nanodet_plus_m_320.onnx
```

## Same-Video Test Protocol

Use one video file on both hosts, for example `data/sample.mp4`, and do not mix
camera input with file input in the baseline table.

Record at least these fields:

```text
host, model, backend, input_size, precision, threads, frame_count,
wall_time_sec, preprocess_ms_mean, inference_ms_mean, postprocess_ms_mean,
end_to_end_fps, detection_count_mean, temp_c_mean, temp_c_max, throttle_ratio
```

For RT-DETR, continue using the existing experiment scripts:

```bash
python scripts/run_experiment.py \
  --config configs/raspberry_pi4.yaml \
  --strategy native_rtdetr \
  --video data/sample.mp4 \
  --duration-min 5 \
  --output experiments/logs/sota_baselines/pi_rtdetr_r18_640.csv
```

For YOLOv8n, run the framework command first to validate outputs:

```bash
yolo predict \
  model=models/baselines/yolov8n_640.onnx \
  source=data/sample.mp4 \
  imgsz=640 \
  device=cpu \
  project=experiments/visualizations/sota_baselines \
  name=local_yolov8n_640 \
  save=True
```

For PicoDet, first validate Paddle inference because it is the official
deployment format:

```bash
python third_party/PaddleDetection/deploy/python/infer.py \
  --model_dir=models/baselines/picodet_s_320_coco_lcnet_portable \
  --video_file=data/sample.mp4 \
  --device=CPU \
  --output_dir=experiments/visualizations/sota_baselines/local_picodet_s_320
```

The checked-in runner points to the portable inference directory generated by
`scripts/prepare_sota_baseline_artifacts.py`. On Windows with Python 3.12,
Paddle 3.3 can load this artifact but may fail inside an old fused convolution
operator. For formal Raspberry Pi results, use a Paddle/Paddle Lite runtime that
matches PaddleDetection release 2.x, or run the Paddle Lite model converted from
the same inference directory.

For NanoDet-Plus, validate with its demo or ONNX path after export:

```bash
python third_party/nanodet/demo/demo.py video \
  --config third_party/nanodet/config/nanodet-plus-m_320.yml \
  --model models/baselines/nanodet-plus-m_320.ckpt \
  --path data/sample.mp4
```

## Pi Suite Script

Use the suite runner for the comparison that belongs in the thesis table:

```bash
python scripts/run_pi_sota_comparison_suite.py \
  --video data/sample.mp4 \
  --duration-min 5 \
  --max-frames 600 \
  --cooldown-temp-c 55 \
  --enable-thread-sessions \
  --thread-session-counts 1,2,3,4 \
  --apply-runtime-actions
```

On the Pi, prepare external baselines first:

```bash
python -m pip install ultralytics onnxruntime gdown
python scripts/prepare_sota_baseline_artifacts.py --models pp_picodet_s_320,nanodet_plus_m_320

test -d third_party/PaddleDetection || \
  git clone --depth 1 --branch release/2.7 https://github.com/PaddlePaddle/PaddleDetection.git third_party/PaddleDetection
test -d third_party/nanodet || \
  git clone --depth 1 https://github.com/RangiLyu/nanodet.git third_party/nanodet
```

It runs:

```text
rtdetr_native_fp32       native RT-DETR baseline
proposed_lk_tracking    proposed detector with event-triggered LK tracking
proposed_software       full software policy: scene + LK + thermal interval control
yolov8n_640             YOLOv8n ONNX baseline
pp_picodet_s_320        PP-PicoDet official Paddle inference baseline
nanodet_plus_m_320      NanoDet-Plus official PyTorch demo baseline
```

Preview without running:

```bash
python scripts/run_pi_sota_comparison_suite.py --plan-only
```

## Raspberry Pi Notes

On Raspberry Pi, run with the same video file and fixed cooling policy. Before
each model, cool down to the same start temperature band, for example below
55 C, or record the starting temperature and report it.

Preferred Pi backend order:

```text
YOLOv8n: ONNX Runtime -> NCNN if ONNX Runtime is too slow
PicoDet: Paddle Lite -> Paddle inference -> ONNX Runtime
NanoDet-Plus: NCNN -> ONNX Runtime
RT-DETR: existing ONNX Runtime pipeline
```

The final table should separate detector fairness from deployment practicality:

| Table | Purpose |
| --- | --- |
| Same backend, ONNX Runtime CPU | Fair runtime comparison where all supported. |
| Best available Pi backend | Practical edge deployment comparison. |
| Same input size subset | Strict accuracy and latency ablation. |
| Native recommended input size | How each model is usually deployed. |
